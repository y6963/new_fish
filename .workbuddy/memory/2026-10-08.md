| summary ≤ 500 字符 | `summary cannot be longer than 500 characters` |
| fact ≤ 250 字符 | `fact cannot be longer than 250 characters` |
| 自环关系禁止 | `source and target node names cannot be the same`（本次 1159 条里 49 条） |
| 属性必须在本体里定义过 | `attribute 'name' is not defined in ontology for labels [Person]` |
| 不能跨图引用节点 uuid | `source_node_uuid … belongs to a different graph` |
→ 因此一致性口径改成「名称 + 类型 + 摘要」与「事实文本 + 两端名字」，uuid 只作参考。

### 全量实测结果（美国中期选举图 349 节点 / 1159 边 / 94 episode）

- 恢复目标 `mirofish_restored_final`：**节点名称命中 100%、实体类型一致 100%**；
  关系 **事实文本命中 93.79%（1087/1159）**，两端实体一致 87.75%；
  时序字段 valid_at 99.81% / invalid_at 100% / expired_at 100%。
- 关系缺口 = 49 条**自环**（Zep 禁止两端同名）+ 少量 fact 重名合并。
- **节点摘要是派生物**：写完关系后 Zep 异步重写摘要，落库后立刻校验一致率 34%，
  放 45 分钟后再校验只剩 2.22% → 摘要不能当一致性硬指标。
- `--nodes-only` 二次覆盖摘要能把一致率拉到 62%，但 **add_nodes 不按名字去重**，
  节点会从 349 翻倍到 708 → 结论：Zep 直写接口下「节点不重复」与「摘要等于原文」不可兼得。
- 耗时参考：1159 条边并发 6 写入约 7 分钟，云端异步落库约 20–45 分钟才稳定
  （`wait_until_stable` 轮询边数）。
